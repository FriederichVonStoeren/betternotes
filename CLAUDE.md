# betternotes: rules for any Claude session

GoodNotes-style handwriting app for iPad (native Swift) plus a PWA companion (Android, Fedora).
Works like GoodNotes, looks like Obsidian, open format, no lock-in.

Read first: `PROGRESS.md` (where we are), `docs/ARCHITECTURE.md` (approved design),
`docs/SCOPE.md` (what to build and what never to build), `docs/DECISIONS.md` (why).

## The owner

A student, not a professional developer. When they must do something (GitHub settings,
SideStore, Azure), give exact click-by-click steps or commands. Keep the code simple enough to
maintain with Claude Code. Plain language in docs.

## Secrets and privacy (the repo is PUBLIC)

- Never commit API keys, tokens, Apple IDs, passwords, signing material, personal notes or
  school files. No secret ever needs to be in the repo.
- Apple ID: only typed on-device into SideStore / iloader. API keys: typed into the app, stored
  locally (Keychain on iPad, encrypted storage on web). The Microsoft client ID is a public PKCE
  client ID and may be committed.
- Test fixtures are synthetic. Real samples go only in `private-samples/` (gitignored), are never
  committed and never quoted in docs.
- If anything sensitive is ever committed: STOP and tell the owner so they can revoke it.
  Deleting it is not enough on a public repo.

## Hard constraints

- No Mac, no paid Apple Developer account. iOS builds run only on GitHub Actions macOS runners.
  Nobody can open Xcode: the project is generated by XcodeGen from `ios/project.yml`.
  Never hand-edit or commit a `.xcodeproj`.
- CI builds an unsigned `.ipa`; the owner sideloads it with SideStore and a free Apple ID.
  So: no iCloud/CloudKit, no push, no special entitlements, **no app extensions** (3-app and
  10-app-ID limits), one app target only.
- Core logic (format, geometry, sync) lives in the Swift package `core/` with unit tests.
  Keep the UI layer thin. Swift is not installed locally: Swift code is verified only by CI.
- No personal backend, no accounts, no telemetry, no paywall. Each user syncs to their own cloud.
- Never build: sticker store, tape tool, audio recording, built-in AI features (the opt-in
  "Ask Claude" / "Research with Perplexity" actions with the user's own keys are the only AI).
- Never lose notes: atomic writes, autosave, backup of the previous version on conflicts and
  migrations. The web app must preserve object types and fields it does not understand.
- UI languages: German and English from the start. Licence: GPL-3.0-or-later (apps),
  CC0 (format spec and schema).

## Workflow

- Work on `main`, small commits, conventional messages. Commit AND push after every milestone
  and every meaningful sub-step. Never force-push.
- After each push: `gh run watch` (or `gh run view --log-failed`). If CI fails, fix it before
  moving on. Download the UI-test screenshots artifact and look at it.
- Tag each finished milestone (`v0.1`, `v0.2`, ...). The tag makes CI publish a GitHub Release.
- Continue through milestones without asking while CI is green. Stop only at CHECKPOINTS
  (owner must test on a device) or when blocked; batch questions into one numbered list.
- At a checkpoint: say exactly how to test, with a done / not-done list.
- Keep `PROGRESS.md` current. Record every architectural decision with its reason in
  `docs/DECISIONS.md`.
- Verify Apple and Microsoft API availability against current documentation before use.
