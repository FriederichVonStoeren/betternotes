# Decisions

Newest at the bottom. Each entry: what was decided and why.

## D1. XcodeGen generates the Xcode project
Nobody on this project has a Mac. A `.xcodeproj` cannot be edited safely by hand, so it is
generated in CI from `ios/project.yml`. XcodeGen is one YAML file; Tuist is heavier; plain
SwiftPM cannot produce an iOS app bundle.

## D2. Custom ink engine, not PencilKit
PencilKit's canvas is a black box: no layers, no own object types, no live mirrored strokes,
no replaceable eraser/lasso (needed for clip-select). We own the stroke model anyway because it
is the file format. Milestone (b) verifies latency with a three-way spike (PencilKit, custom,
PencilKit-live-then-convert). First renderer is Core Graphics; Metal only if the spike needs it.

## D3. One file per page, notebook as a plain folder
Minimises sync conflicts and keeps the format inspectable. Pages carry their own chapter id and
sort key so that adding or moving a page does not touch `notebook.json`.

## D4. Stroke points are rounded integers in parallel arrays
x/y in 1/100 pt, pressure 0..1000, tilt/azimuth/roll in 1/10 degree, time in ms since stroke
start. Smaller files, and no floating-point differences between Swift and TypeScript.

## D5. Swift keeps a raw JSON tree under the typed model
`Codable` silently drops unknown fields. Preserving unknown fields and object types on save is
the forward-compatibility rule, so the Swift package reads and writes through a `JSONValue`
tree. Conformance tests compare parsed content, never bytes.

## D6. Sync: OneDrive app folder, hand-written PKCE, eTag checks
Scope `Files.ReadWrite.AppFolder` (owner's choice): the app sees only its own folder. PKCE by
hand instead of MSAL, because MSAL on iOS wants a keychain-sharing entitlement that is risky
with free-account sideloading. Uploads use `If-Match`; a mismatch creates a conflict copy, never
an overwrite. The sync-state file is per device and never uploaded. `notebook.json` is merged
automatically (chapters by id, tags as a set, newer wins per field); page files never are.
The decision logic is storage-neutral and lives in `core/`.

## D7. One app target, no app extensions
A free Apple ID allows 3 sideloaded apps and 10 app IDs per week; each extension costs an app ID.

## D8. Licence: GPL-3.0-or-later for apps, CC0 for the format
Owner's choice. The apps stay open; anyone may implement the format.

## D9. Deployment target iPadOS 18.0, Swift 5 language mode
18.0 covers all Pencil Pro APIs. Swift 5 mode avoids Swift 6 strict-concurrency errors, which
are expensive to fix when every compile is a CI round trip.

## D10. Info.plist is generated by build settings
`GENERATE_INFOPLIST_FILE` with `INFOPLIST_KEY_*` settings in `project.yml`: no plist file to
maintain. Switch to a real plist when a key is needed that has no build setting (URL scheme for
the OAuth redirect).

## D11. Commits use the GitHub noreply address
The repo is public; the repo-local git identity is the owner's GitHub noreply e-mail.

## D12. First install of SideStore from Fedora uses iloader
iloader (github.com/nab138/iloader) ships an RPM, installs SideStore and places the pairing
file. Checked 2026-11: v2.4.1, actively maintained.

## D13. The latency spike has three modes, including a hybrid
PencilKit (reference), the custom engine, and hybrid (PencilKit draws while the pencil is
down, our renderer replaces the stroke at lift-off). Hybrid is the fallback if the custom
engine feels clearly worse; the spike shows whether its jump at lift-off is acceptable.

## D14. GitHub Pages is deployed by a workflow, not from a branch
The `pages` CI job builds the site from `site/`, `spikes/` and `schema/` and generates the
SideStore source `apps.json` from the releases. Nothing generated is committed.

## D15. The OneDrive spike is a single static page
`spikes/onedrive/` does PKCE by hand against the `common` endpoint with
`Files.ReadWrite.AppFolder`, so the owner can test a school account in a browser months
before sync is built. Tokens stay in memory; only the public client ID is kept in localStorage.
